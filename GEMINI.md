# ZEDDA Project Rules

1. Never hand-write, describe, or remember example terminal output. Any output shown as "proof" must be the literal, unmodified stdout of a command you just ran — paste the real content, not a retyped or paraphrased version.
2. Never add a new feature, command, CLI flag, or behavior that wasn't explicitly requested in the current task, even if it seems related or helpful. If something seems missing, name it as a suggestion at the end of your response — do not build it.
3. Never mark something FIXED, DONE, or IMPLEMENTED without pasting the real output that proves it, in the same response.
4. If a prior decision in this project's history was explicitly marked "out of scope" or "rejected," do not silently re-introduce it. If you think it should be reconsidered, say so explicitly and ask first.
5. When a task lists multiple numbered items, respond to every single one — do not silently skip items. If you didn't get to something, say "not attempted," don't just omit it.
